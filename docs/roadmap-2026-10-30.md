## 2. 10 月 30 日交付定义

用户提供当前水平、目标、剩余天数与每日时长后，Skill 能建立档案并给出有限时间内的阅读训练优先级；从题库选基线题，判分后提出至少两个可区分的错误原因假设，通过最多 2～3 轮针对性追问或验证任务收集证据；给出与证据对应的策略和未做过的训练题；再用**未见过的文章**复测，更新能力状态并保存档案；下一次会话可以继续。

文章正文只从 `data/passages.json` 读取。`data/questions.json` 用 `passage_id` 引用正文，不复制 `text`。选题与去重以篇为边界，避免同篇的其他题在复测中泄漏文章内容。无可靠答案或证据时，保留不确定性，不宣称已掌握或推算真实考试分数。

交付包：`skill.md`、完整 `references/`、30～50 道经人工核对的题、策略库、三个确定性 Python 工具、档案结构、自动化测试、两条完整演示会话和简短运行说明。建议冲刺 40 题（8 篇 × 5 题），最低接受 30 题（6 篇 × 5 题），但题型标签及训练/复测文章覆盖必须满足真实闭环。

## 4. 两条并行工作线

**邹婧媛：AI / Skill。** 先完成可执行的诊断规则，尤其区分“观察到的错”与“推测的根因”；规定何时继续追问、何时停止、何时保留 `pending`。随后完成时间预算规划、选题、策略注入和迁移复测规则。`skill.md` 负责串联工具、隐藏未答题答案、处理工具异常与会话恢复。

**蔡佳仪：数据 / 工具。** 先固定 JSON 接口与 `passage_id` 关联；三个脚本只做可复核的确定性操作。题库按篇录入和人工核查，避免同一篇的多题重复计入迁移证据。`profile.json` 记录每位用户的已见文章/题目、答题与诊断证据、能力状态及目标预算。全局 `questions.json.used_count` 不能代替用户级去重；若保留该字段，应明确其统计用途和更新时机。

## 5. 关键验收门槛

1. **数据正确性**：题目 ID 唯一；每题 `passage_id` 在 `passages.json` 中存在；选项 A–D、答案、标签、来源和解析齐全；标签属于 `taxonomy.md` 的 8 个题目能力标签。
2. **检索与判分**：`search_questions.py` 按标签、难度、数量与用户已见文章过滤，返回不含答案的标准 JSON；题量不足时明确返回实际数量与原因。`grade_answers.py` 只接受合法题号和 A–D 答案，结构化返回对错、正确答案与解析。
3. **诊断可信度**：错题至少提出两个合理假设；2～3 轮追问后，根据证据支持、排除或保留假设，不能把题目标签或干扰项类型直接当作用户根因。
4. **迁移与持久化**：复测文章与基线/训练文章不同；能力状态命名在 10/15 冻结，并与 `taxonomy.md`、档案和 Skill 一致；重启后保留历史、已见集合和下一步安排。
5. **演示稳定性**：交接手册 8 项验收全部通过；两条完整会话可复现；离线本地数据与 Python 工具即可运行。

## 6. 立即决策与风险

- **10/15 前统一状态词。** 交接手册使用 `pending → supported → mastered`，现有 taxonomy 使用 `pending / initially_supported / not_supported_this_time`。应在接口文档中定义“单次诊断证据状态”和“跨文章掌握度状态”两个不同字段，避免直接混用。
- **10/15 前确定题库配额。** 先选 6～8 篇原档形成 30～40 题，并把至少两篇留给复测场景。若某稀有标签不足以跨篇训练与复测，演示时不宣称该标签已掌握。
- **10/17 前修正抽取脚本路径并核对来源。** `passages.json` 已有正文，因此此项是可再生性与一致性修复，不阻塞先实现读取现有 JSON 的闭环。
- **策略必须受原文证据约束。** “绝对词”“选项长短”等只能提示检查，不能作为独立判题规则；策略库应包含适用条件、反例/限制和对应根因。
- **范围控制。** 10/21 后不增加新题型、前端、数据库或复杂推荐算法。若落后，优先保住 30 道高质量题、双篇迁移复测、持久化和 8 项验收。

## 7. 每日同步机制

每天结束前同步四个数字：已人工核对题数、可用于复测的独立文章数、8 项验收通过数、阻断问题数。任何接口变更先改 `docs/requirements.md` 和样例，再同步 Skill、脚本与测试；10/25 后除修复阻断问题外冻结数据结构。
